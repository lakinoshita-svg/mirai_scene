# ミライシーン 現行仕様書 — 作業者向け

更新日：2026年10月2日

この資料は、制作を依頼し、内容を確認する担当者向けです。コードやデータを直接編集する必要はありません。AIや開発担当者が使う詳しい決まりは、[AI・開発担当者向け仕様書](CONTENT-SPEC-AI.md) に分けています。

## 1．背景：なぜ作るのか

進路ナビは「“好き”から始まる進路選び」を大切にしています。高校生の中には、将来やりたい仕事をまだ言葉にできない人がいます。学校名や職業名を選ぶ前に、「少し気になる」「これは面白そう」と感じられる入口が必要です。

進路ナビには、適性・適職診断、分野について調べる教材、学校の情報があります。ミライシーンは、仕事のひと場面を体験することで、それらの情報と自分の興味をつなぐために企画しました。

進路ガイダンス後の利用も想定しています。ただし、参加していない人も使います。「ガイダンスで気になった仕事」など、参加者にしか通じない説明にはしません。

## 2．目的：どうなってほしいか

仕事の中のどんなことに興味があるか気づき、その先の学びや学校を調べるきっかけをつくります。

例えばデザインの体験で、「絵を描くこと」だけでなく「相手の話を聞いて、伝わる形を考えること」に興味を持つかもしれません。

点数を付けたり、向いている職業を決めたりするサービスではありません。資料請求も、進路を決める前の情報集めの一歩として案内します。

## 3．概要：どんなサービスか

**体験を選ぶ → 3つの場面で考える → 解説を読む → 気持ちを振り返る → 学び・学校を調べる**、という流れです。

感想のボタンを選ぶと、まだ言葉にできない気持ちを代弁する返答が表示されます。正解や適性を判定するための質問ではなく、体験への理解を深めるきっかけです。選び直したり、選ばずに進んだりできます。

体験完了後は、学校検索、関連する教材、資料請求の説明、同じ分野の教材・仕事体験、別の気になる仕事の順に案内します。

| 項目 | 現在の決まり |
|---|---|
| 利用する人 | 高校生。ガイダンス参加者と一般の訪問者の両方 |
| 1つの体験 | 3つの場面。それぞれ3つの選択肢から選ぶ |
| 時間 | 約3分が目安 |
| 答え | 1つの正解を当てる問題にしない |
| 解説 | 状況を整理する共通説明と、選択ごとの説明・良い点・懸念点 |
| 画像 | 見比べる必要がある場面などで使う |
| 体験の種類 | つくる・表現する／人の役に立つ／しくみを考える／知らない世界に触れる |
| 今後の数 | 約300体験。同じ職業でも違う題材で複数作れる |

選択によって次の場面は変わりません。回答は保存されず、ページを読み込み直すと最初からになります。原稿と画像は先に制作・確認して用意します。閲覧のたびにAIが生成する方式ではありません。

## 4．内容を確認する基準

自社書籍や進路ナビの情報を土台に、実際の仕事の描写を厚生労働省の「job tag」などで補います。資料を読んだことと、専門家に確認してもらったことは別です。

**良い例**：「ポスター完成まで2日。最初の30分で、参考例を集めるか、依頼内容を確認するか、簡単な案を作るかを考える。」仕事・期限・考えることが分かり、各方法に良い点と追加で確かめたい点があります。

**直したい例**：「仕事で困りました。頑張りますか、相談しますか、放置しますか？」何に困っているかが分からず、仕事の考え方も伝わりません。

## 5．担当者が行うこと

### 手順1：制作を依頼する

このプロジェクトを開いた状態で、下の文章をコピーしてAIへ渡します。職業と件数を変更してください。

```text
ミライシーンの体験を2件作成してください。
職業は図書館司書です。既存の体験と題材が重ならないようにしてください。
AGENTS.mdとdocs/CONTENT-SPEC-AI.mdを読み、案内される制作ガイド・資料・台帳を確認してください。
今回は下書きまでです。公開や初期導入ZIPの変更はしないでください。
作成後は、画面で確認する方法と、私が確認する点を分かりやすく示してください。
未確認の内容があれば、完成したと言わずに教えてください。
```

別担当者には、この資料だけでなく最新のプロジェクト一式も渡します。AIがファイルを読めないと答えた場合は、読んだことにして進めず、共有方法を開発担当者に確認してください。

### 手順2：画面や原稿を読む

一度に2〜5件程度を確認します。自分で選んで解説まで読み、次を確認します。

- どんな場面で何を考えるのか分かるか。
- 選択肢の違いが分かるか。
- 行動と、その良い点・気をつける点がつながっているか。
- 高校生が知らない言葉に説明があるか。
- 学びや学校の案内は、体験と関係しているか。

業務として正しいか判断できない文は「分からない」と記録し、内容を確認できる部署へ回します。AIの「チェック成功」は、仕事の内容がすべて正しいという意味ではありません。

### 手順3：直してほしいところを伝える

「図書館司書の2つ目の場面で、AとBの違いが分かりません。違いが伝わるよう直してください」のように、体験名と場所を指定します。修正後はもう一度読んでください。

### 手順4：確認結果を残す

確認した人・日付・直した箇所・まだ分からない点を残します。AIには「今回の結果をレビュー記録と制作台帳に残してください」と伝えられます。

別部署へExcelで渡すときは対象原稿を指定してAIへ依頼します。現在の通常のExcel出力には制作途中の原稿は含まれないため、必要な原稿が入っていることを確認します。

### 手順5：公開担当者へ渡す

内容の確認が終わっても、自動では公開されません。「確認済み」と「公開済み」を分けて記録し、更新内容と確認結果を公開担当者へ渡します。

## 6．導入用と制作中のものを分ける

| 名前 | 用途 | 扱い |
|---|---|---|
| 初期導入用ZIP | 最初に進路ナビへ入れる19体験の固定ファイル | 中身を直接編集しない |
| 制作中の原稿 | 追加体験や修正案 | 内容を確認し、直してもらう |
| 公開用の原稿 | 次の公開に使う編集元 | 確認済みの内容を公開担当者が反映する |

ミライシーンの制作元はGitHub、進路ナビ本体はGitLabという別の場所で管理しています。このプロジェクトを直しただけでは、進路ナビ本番には反映されません。

初期導入用ファイルを作る仕組みはあります。追加コンテンツだけを安全に取り込む専用の仕組みは未実装です。配置や、進路ナビ側の変更とぶつからないかの確認は開発担当者が行います。

## 7．困ったとき

| 困ったこと | 次にすること |
|---|---|
| AIの説明が分からない | 「私が確認することを順番に説明してください」と伝える |
| どの資料を読むか迷う | 担当者はこの資料。AIにはAI向け仕様書とAGENTS.mdを指定する |
| 原稿と画面が違う | 体験名と違う文章をAIへ伝える。ZIPを直接編集しない |
| 内容の正しさが分からない | 不明な文を記録し、その分野を確認できる部署へ依頼する |

詳しい基準は [制作引き継ぎガイド](editorial/HANDBOOK.md)、進行状況は [制作台帳](CONTENT-BATCHES.md) を参照してください。

## 用語の方針 2026年10月7日

「探究」は広い意味と深く学ぶ活動を含むため、機能名・コンテンツ名・見出しとして名詞で使用しない。画面では内容に合わせて「学びの分野」「この分野で学ぶこと」「関連する教材」「教材を読む」など、遷移先が分かる表現を使う。「探究する」という動詞としての使用は可能。

制作する画面・文章・企画書・マニュアルに適用する。引用元の原文や正式名称、過去の確認記録・固定配布物は改変しない。公開URLのexplore、内部のinquiry、教材slugなどの識別子は変更せず、表示名称と分けて扱う。
