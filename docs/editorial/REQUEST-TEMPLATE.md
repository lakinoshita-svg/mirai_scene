# 別担当者・別Codexへの制作依頼テンプレート

以下をコピーし、角括弧の箇所を埋めて渡してください。初回は2件程度で判断基準を合わせます。

```text
このリポジトリのミライシーンを制作してください。
過去のチャットは前提にせず、AGENTS.mdから制作引き継ぎガイド、現行仕様、資料対応表、制作台帳を読んでください。

依頼：［新規制作／既存原稿の改稿／原稿レビュー］
対象：［職業・slug・題材。未指定なら重複しない候補から選ぶ］
件数：［2件など］
バッチ：［batch-002など。既存バッチへ無断で上書きしない］
重点：［仕事の具体性／選択肢の比較／画像など］
追加資料：［リポジトリ内のパス、またはなし］
作業範囲：下書き制作と検証まで。公開元への移動・本番公開・初期導入ZIPの変更は今回の対象外です。

1体験は3シーン、各3選択肢。共通解説に状況整理を入れ、各案に説明・良い点・懸念点を付けてください。
ガイダンス参加者だけを想定せず、正解当てや適性判定にしないでください。
自社資料の対応を確認し、実務描写は一次資料を読んで補ってください。未確認の資料・監修・確認日を創作しないでください。
原稿はdrafts/<バッチ>/へ置き、REVIEW-TEMPLATE.mdを基に同じフォルダへREVIEW.mdを作成してください。
既存の分類・学びIDを使い、追加が必要なら理由と影響を示してください。
制作後はハンドブックの全観点で自己レビューし、指摘を修正してから隔離ビルドしてください。
資料が不足する場合は、確認できる部分の制作を進めつつ、不明点と影響する文をレビュー記録へ残してください。
台帳を更新し、完成件数、検証結果、未確認事項、変更ファイルを報告してください。
```

レビューだけを依頼する場合は、最後に次を追加できます。

```text
今回は評価と修正案の提示をしてください。各指摘はslug・scene id・option idまたは項目名、問題の文、理由、修正案をセットで記録してください。
ビルド成功を内容確認済みとは扱わず、同じ基準例と判定表を使用してください。
```
