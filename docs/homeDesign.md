# TOPデザインの判断基準

各要素の役割と実装上の判断を示す。効果測定の結果とは区別する。

## 目的

将来の仕事をまだ言語化できていない高校生が、気になるひと場面を選んで体験を始められること。ガイダンスの参加は前提にしない。

## 各要素の役割と配置

| 要素 | 役割 | 配置の判断 |
| --- | --- | --- |
| 共通ヘッダー | 進路ナビのナビゲーション | 本体の共通ヘッダーを使用 |
| サービス名 | 体験コンテンツの名前を示す | 本文先頭に文字ロゴを中央配置 |
| FVの短い説明・見出し | 何のサービスか、何が得られるかを伝える | 文字は左揃え。見出し・説明・CTAを一つのまとまりとして中央に配置し、写真と別の列にする |
| 紫を中心とするグラデーション | 興味から一歩踏み出すブランドの雰囲気 | 見出しに限定したアクセント。本文は単色で読ませる |
| 人物の3枚の写真 | 仕事の広がりを具体的にイメージする | 説明用のためリンクを付けず、文字が隠れない大きさと重なりにする |
| CTA | 体験一覧へ進む | 説明のすぐ下。同じ左端。SPでは写真より先に配置 |
| 約3分・3シーン・登録不要 | 開始に必要な手間を示す | CTAの近くでまとめて伝え、各カードでは繰り返さない |
| 興味カテゴリー | 職業名を知らなくても選べる入口 | キーワード欄より前。SPは2列、未選択の入口は全幅 |
| キーワード・職業分野 | 具体的に探せる人を支える | カテゴリーより小さな階層で表示 |
| カード | 職業の題名より、体験する状況への関心を促す | テーマ画像の面積を抑え、体験タイトルを強調。SPは横型 |
| もっとみる | 興味を探す候補を段階的に増やす | FVの主CTAより控えめなアウトライン。PC9件・SP8件ずつを維持 |
| 教材への入口 | 学ぶ内容から探したい人の別ルート | 一覧の後に淡色の独立した領域として設置 |
| about案内 | 体験をどう捉えるか補足する | 学びの案内と同じ内側余白・リンク列で配置 |

## 編集・確認

通常表示のFVはPC・SPとも650px以内（外枠・サービス名・パンくずを除く）。SP画像領域は高さ260px・最大幅320px。上下余白はPCが16px・24px、幅900px以下が8px・8px。単独公開用ヘッダーはPC48px・幅650px以下40px。本文先頭のサービス名は上下8px。パンくずは行高18px・上下8px。文字拡大時は自然な高さを許容する。

Figma：[PC 1280](https://www.figma.com/design/Qs575HHeLxhbfPWFZrBw5D?node-id=36-22)／[SP 390](https://www.figma.com/design/Qs575HHeLxhbfPWFZrBw5D?node-id=42-64)。Webとの自動同期は行わない。運用手順は `outputs/operations/運用マニュアル.html` を参照する。

- FV：`src/components/hero.astro`。文字・CTAを画像と同じ絶対座標で固定しない。
- TOP一覧と下部：`src/styles/homeStyles.css`、`src/pages/index.astro`。TOP専用のCSSは`.homePage`内に限定する。
- 検索UI：`src/components/careerCatalog.astro`。データ属性と検索ロジックの接続を維持する。カテゴリーは既存のJSONを使用する。
- 見た目だけでなくカテゴリー切替、キーワード検索、PC9件・SP8件の追加表示、CTAの一覧への移動を確認する。
- 小画面ではCTAを初期画面内に置くことを優先する。ただし文字拡大時に高さを固定して切り取らない。
- 写真は3つの仕事イメージ、検索は4つの興味分類で役割が異なる。写真をクリック可能な分類ボタンのようには扱わない。
- 固定導入ZIPとFigmaは別成果物。コード変更だけで更新済みと案内しない。
